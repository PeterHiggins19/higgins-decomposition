# Expert communication & the learning path — the consolidated method

*Everything the Hˢ project has learned about reaching experts, onboarding them, and the learning path
for both human users and the AI assistants that help them. One place, so the voice stays consistent
across every folder, paper, and assistant. Machine-readable twin: `EXPERT_COMMUNICATION_AND_LEARNING_PATH.json`.
Author: Peter Higgins (human authorship for claims); AI-assisted per HUF-STD-001. Honest-broker.*

---

## Part I — Communicating with experts (the doctrines)

1. **The composition is the qualifier.** Hˢ is an expert system; the repositories are its expert
   onboarding. If you have a composition — parts of a whole tracked in order, within a shared budget —
   you already have the need. If you do not, this is not your tool. State the purpose at the front door
   so no one's time is wasted.

2. **The exclusive club is kind.** The rejection is friendly and humble — *"sorry, compositions only"* —
   explained, with better-suited methods named and goodwill offered. Win-win-win: a clean fit for those
   inside, an honest redirect for those outside, no time lost either way.

3. **No advertisement.** Tell it, show it, offer it for reproduction — then stop. No selling, no
   trials-and-tribulations backstory. The audience that can use this already has the concept of need;
   advertising is wasted resource. Get to the point.

4. **Don't narrate intent.** The failure mode (learned the hard way): documents that *protest* "this is
   not outreach, no reply wanted" read as desperate for a response. Write to a *phantom audience of
   experts* — make the work legible to the leading people in the field — but never address them and
   never explain intent. Confidence in what is provable; silence on what is not.

5. **Names off the repo unless cited.** A target expert audience is a fine *writing instrument* to keep
   work directed — but the name stays off the public repo, in off-repo planning. A published-paper
   citation (author-year/title/venue) is scholarship and is welcome; naming a person as a
   contact/target is not. Make no claim of a collaboration that does not exist; act purely as
   inspiration to test and extend good work. Names move on-repo only when an official collaboration
   actually exists.

6. **Match the register to the audience.**
   - *Science community* → honest tiers and reproduction first; the work argues for itself.
   - *Power/confidence communities (e.g. finance)* → lead with provable certainty and reproducibility,
     then temper with the science declaration of **bias, limits, and bounds**. The confidence is
     epistemic (certainty about what the data reveals + that it reproduces), never a claim about the
     future. An instrument that refuses to bluff is one whose every reading can go to the table.

7. **The honest envelope, always.** Tier 1 (verified, reproducible) vs Tier 3 (the expert's meaning).
   Holds-or-warns rather than return a confident wrong answer. Descriptive, not advice — emphatically in
   finance and medicine (not investment advice; not clinical). Public, aggregate data only on the repo.

8. **Paper / repository division of labour.** Higher intelligence → the paper; the vast data effort →
   the repository; a receipt binds them. (See `papers/PAPER_AND_REPO_DIVISION.md`.)

## Part II — Onboarding (the gate, then the graduated induction)

- **The hard go/no-go gate.** One question — *do you have a composition?* — answered interactively by
  [`COMPOSITION_GAUGE.html`](COMPOSITION_GAUGE.html) and in prose by [`IS_Hs_RIGHT_FOR_YOU.md`](IS_Hs_RIGHT_FOR_YOU.md),
  with the reasoning shown at each negation step. Three outcomes: **GO**, **NO-GO** (kind redirect), and
  the **HIGHER DOOR** — your raw data isn't a composition, but a composition *of your samples, methods,
  or the observers who study your subject* might be. Study the studiers.
- **The graduated induction.** After the gate, [`INDUCTION_MAP.md`](INDUCTION_MAP.md) (+ `.json`): seven
  stages — orient → fit-by-D → run-your-data → branch-by-discipline → branch-by-purpose → playground →
  graduate — each with its own small pass-gauge. Graduated, not permission-gated: advance on passing
  each gauge; skip ahead if already qualified.

## Part III — The learning path

**For users.** Pass the gauge → learn what Hˢ gives at your D → run your own data and get a receipt →
find the worked run nearest your field → pick your purpose (read motion, monitor, control, characterize,
extend, publish) → experiment in the playground → graduate to a reproducible, traceable node.

**For AI assistants.** Every domain folder carries an `AI_ASSIST.json`; the assistant protocol is fixed:
1. **Gate first.** Confirm a composition. If the user wants advice, a forecast, or a probability, say
   plainly Hˢ does not produce those and stop — kindly. Deliver only *what the data reveals*.
2. **Compose on request.** Turn the system the user operates into a composition (rows = order, columns =
   parts summing to a whole); validate with the gauge; keep private data local.
3. **Run + receipt.** Always surface the `content_hash`; never report a result without it.
4. **Translate.** Map the reading into the user's own field language.
5. **Hold the bounds.** Tier 1 reading vs Tier 3 meaning; descriptive not advice; holds-or-warns; public
   framing on anything shared.

## Throughline

The same discipline runs from the engine to the outreach: **non-perturbing, honest, reproducible.** The
instrument doesn't disturb the data it reads; the communication doesn't disturb the reader it offers
itself to; the onboarding wastes no one's time; the assistant refuses to bluff. The data is the star;
Hˢ is the lens; the receipt is the proof — and that holds in the science *and* in how we speak about it.

*Tell it, show it, offer it for reproduction. Gate kindly. Match the register. Cite, don't name. One
idea per paper, fully reproducible below it.*
